How memories work in this repo

Lesson 0001 · mcp-memory · one memory, from write to recall

This server exposes exactly two memory tools — remember and recall (MCP tools registered in index.ts). There is no database. Every memory is a single vector in a Cloudflare Vectorize index, and the original text rides along inside the vector's metadata. Understanding this one pipeline is the foundation for everything else in the repo.

The write path: remember

When a client calls remember with some text, VectorMemoryStore.persistMemory() (memory-store.ts) does three things:

  1. Validates the text (non-empty, ≤ 2000 characters).
  2. Embeds it with Workers AI's @cf/qwen/qwen3-embedding-0.6b model, using the { documents: [text] } input shape.
  3. Upserts one vector into the MEMORIES index.
await index.upsert([{
  id,            // crypto.randomUUID()
  values,        // the embedding (a number[])
  namespace,     // SHA-256 hex of the Clerk user ID
  metadata: {
    text,                        // the original memory, in full
    createdAt:    "2026-…",      // ISO timestamp
    createdAtDay: 20487          // integer epoch day, for filtering
  }
}]);

Key insight

Namespaces are the isolation boundary. The server hashes the authenticated Clerk user ID with SHA-256 and uses that hex string as the vector's namespace. Vectorize namespaces partition an index, so one user's vectors can never surface in another user's search — enforced at query time, not by application code. (Vectorize namespaces)

The read path: recall

recallMemories() mirrors the write path with two deliberate differences:

  1. The query is embedded with the { queries: [text] } shape, not documents. The Qwen3 embedding model is asymmetric: it produces different (better-matched) vectors depending on which side of a search you're embedding.
  2. The query is scoped to the user's namespace and can carry a metadata filter: createdAtDay: { $gte: … } implements the maxAgeDays option. This is why the store saves the integer epoch day alongside the ISO string — Vectorize filters compare numbers, not dates. (Metadata filtering)

Results come back with returnMetadata: "all", so the text the user sees is read straight out of the matched vector's metadata — plus a similarity score.
