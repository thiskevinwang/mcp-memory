# Workers Best Practices Review — mcp-memory

**Sources retrieved:** [Workers Best Practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/) (updated 2026-08-20), local `wrangler/config-schema.json` (wrangler 4.127.1), `@cloudflare/workers-types` — local 5.20260828.1 is *newer* than npm latest (5.20260822.1), so local types win.

**Validation:** `tsc --noEmit` ✅ clean · `wrangler deploy --dry-run` ✅ bindings resolve

## Findings

### [HIGH] JWT audience validation is commented out

`clerk-token-verifier.ts:222` — `// audience: resourceUrl.href,` inside `jwtVerify`. Without audience/resource checks, a token minted for *any* Clerk application is accepted by this server (token-reuse across resources). The opaque-token resource check at `clerk-token-verifier.ts:299–306` is commented out too, and `toAuthInfo` synthesizes a fake 8-hour `expiresAt` (line 343) because introspection doesn't return one. MCP's auth spec expects resource-scoped tokens ([MCP authorization](https://modelcontextprotocol.io/specification/draft/basic/authorization)).

**Fix:** re-enable `audience: resourceUrl.href` once Clerk issues resource-indicator tokens for this server; if Clerk can't, document why and track it — don't leave it silent.

### [MEDIUM] Authorization policy hardcoded in source

`index.ts:50` — `const ALLOWED_EMAIL = "kwangsan@gmail.com";`. Not a secret leak, but it means changing the allowlist requires a deploy, and it's a personal email in version control.

**Fix:** move to a `vars` entry (e.g. `ALLOWED_EMAILS`) — it's non-secret config, so `vars` in `wrangler.jsonc` is fine.

### [MEDIUM] JWKS set re-created on every token verification

`clerk-token-verifier.ts:56` — `createRemoteJWKSet(...)` is called *inside* `verifyAccessToken`. jose caches fetched JWKS **per instance**, so this refetches Clerk's keys on every request — needless latency on the auth hot path, and a Clerk JWKS outage would instantly break all auth.

**Fix:** hoist it to module level (or memoize per issuer). Safe here — it's config, not request-scoped state.

### [LOW] Full introspection result logged

`clerk-token-verifier.ts:295` — `clerk_opaque_introspection_result` logs the entire Clerk response (`sub`, `scope`, `client_id`…). `formatConsoleLog` in `index.ts` additionally appends properties (including email) for all Clerk auth logs. With `head_sampling_rate: 1`, this PII lands in Workers Logs at full volume.

**Fix:** log selected fields, as `logVerifiedToken` already does.

### [LOW] `head_sampling_rate: 1` in committed config

`wrangler.jsonc:11` — fine while developing, but 100% head-based sampling is expensive/noisy at production scale. Revisit when you add environments.

### [LOW] Tests run under `bun test`, not the Workers runtime

`package.json` — the DI-based tests are good, but the canonical setup is [`@cloudflare/vitest-plugin`](https://developers.cloudflare.com/workers/testing/vitest-integration/), which runs tests *inside workerd* and catches runtime/compat differences bun won't. Worth migrating before the cross-user work adds isolation-critical tests.

## Verified clean ✅

- **Config:** recent `compatibility_date` (2026-08-28), `nodejs_compat` on, JSONC, secrets via declarative `secrets.required` (not in source), observability enabled, `main` present.
- **Types:** `Env` generated by `wrangler types`, `satisfies ExportedHandler<Env>`, no `any`/double-casts on handlers, binding names match config exactly (`MEMORIES`, `AI`).
- **Patterns:** no module-level request state (`createWorkerApp(env)` is per-request), no floating promises (all `fetch`es awaited), bindings used instead of REST APIs for Vectorize/AI, no `passThroughOnException`.
- **Security:** `crypto.randomUUID()` and `crypto.subtle.digest` (not `Math.random()`), unknown JSON validated with type guards (`isClerkBackendAccessTokenResponse`) rather than asserted.
- **Streaming:** `await response.json()/text()` only on Clerk API responses — small and bounded, not user-controlled payloads. No violation.
